# 按样卷处理提交异常设计

## 目标

样卷确认完成后，以单个样卷为边界处理学生提交异常，避免不同样卷的异常学生混在同一个队列中。老师只查看存在异常的样卷，并通过整页作业预览完成判断。

## 流程

1. 老师在样卷确认阶段编辑并确认全部样卷。
2. 系统按样卷分别检查学生提交，只保留存在异常的样卷。
3. 如果所有样卷均无异常，直接创建作业或考试并开始 AI 分析。
4. 如果存在异常，页面原地切换到异常处理阶段。
5. 老师依次处理每个异常样卷内的异常学生。
6. 当前样卷处理完成后，自动定位下一份异常样卷。
7. 全部异常样卷处理完成后，老师点击“确认异常并开始分析”。

## 页面结构

异常处理阶段采用顶部导航加三栏布局：

- 顶部横向展示异常样卷导航，仅展示存在未处理或已处理异常的样卷，不展示无异常样卷。每项显示样卷名称和待处理人数；样卷较多时支持横向滚动。
- 选中样卷后，左侧只展示该样卷的异常学生。不同样卷的学生不会出现在同一学生列表中。
- 中间展示当前学生的整份作业，以单页大幅画布呈现，支持逐页切换，不使用缩略图作为主要预览。
- 右侧展示当前异常说明和处理操作。

老师可以返回已处理的异常样卷复查。当前样卷全部处理后，系统自动切换到下一份仍有待处理学生的样卷。

## 异常类型与操作

只支持以下两种异常：

### 缺页

- 展示该学生已扫描的全部页面和缺失页位置。
- 缺失页在页码导航中以虚线状态标记。
- 老师查看现有页面后执行“确认缺页并继续”。

### 未识别学生

- 展示未识别提交的全部页面，姓名区域显示“未识别”。
- 右侧使用支持搜索的分组学生选择器，不直接平铺少量候选按钮。
- 第一组为“优先推荐”，展示当前班级内尚未识别到该样卷作业的学生；第二组为“全部学生”，展示班级完整名单。
- 输入姓名搜索时，两组同步过滤，符合条件的优先推荐学生仍排在前面。
- 已有其他作业归属的学生仍可从“全部学生”选择，避免系统数据有误时无法纠正。
- 老师选中学生后，点击“归属给 XXX”完成归属，学生名称同步更新，并自动进入下一条待处理异常。

不再展示或处理“多页”“重复提交”“归属待确认”等旧类型。

## 状态与文案

- 样卷确认阶段存在异常时，主按钮显示“确认样卷，处理 N 份异常样卷”。
- 每个存在异常的样卷在标题栏右侧展示异常类型标签；无异常样卷不展示任何占位文案。
- 缺页标签按受影响学生去重计数，文案为“缺页 N 人”；未识别学生标签按未识别页面计数，文案为“未识别 N 页”。
- 两类标签均可点击。点击后页面原地进入该样卷的异常处理区，并自动定位到所点击类型的第一条待处理异常，不混入其他样卷。
- 从标签进入处理区后，老师可以处理当前类型、切换当前样卷的其他异常，或返回样卷确认区；已完成结果保留，直至老师返回修改样卷并触发重新计算。
- 横向样卷导航显示每份样卷剩余人数，不额外展示独立的整体处理进度。
- 已处理完的样卷标签显示“已处理”，仍可点击返回复查。
- 当前仍有未处理学生时，底部按钮不可开始分析，并显示剩余人数。
- 全部处理完成后，按钮显示“确认异常并开始分析”。
- 返回修改样卷会清空本轮异常处理结果，并重新按样卷计算异常。

## 数据边界

- 每条异常必须包含 `groupId`，用于关联唯一的样卷。
- 页面通过 `groupId` 先筛选样卷，再渲染该样卷的学生异常。
- 演示数据提供班级完整学生名单，以及每份样卷当前已识别到作业的学生名单；两者求差集得到“优先推荐”。
- 未识别作业的临时选择只保存在当前页面状态中；点击确认归属后才写入异常记录并标记完成。切换学生、样卷或页面不会误提交临时选择。
- 处理结果仍随采集任务快照保存，但读取和展示始终按样卷分组。
- 无异常样卷不进入异常导航，也不产生额外确认步骤。

## 验证

- 流程测试验证异常能按 `groupId` 分组，且无异常样卷被排除。
- 页面测试验证异常样卷导航、样卷内学生列表和整页预览存在。
- 页面测试验证每份样卷只展示自身的异常标签，标签计数单位正确，并能按样卷与异常类型定位处理项。
- 页面测试验证异常样卷导航位于工作区顶部，左侧不再重复显示样卷导航。
- 页面测试验证未识别作业按“优先推荐 / 全部学生”分组，支持搜索、选择和确认归属。
- 页面测试验证仅包含“缺页”和“未识别学生”，不再包含“多页”。
- 完整回归测试验证无异常任务仍可直接开始分析，历史状态和作业创建流程不受影响。
