# 样卷删除与逐题确认进度设计

## 目标

修正样卷删除确认按钮无响应的问题，并区分整个样卷与单页的删除风险。同时让批改页所有题目从“待确认”开始，由老师逐题确认，刷新页面后继续保留确认进度。

## 删除交互

### 整个样卷

- 待确认编辑页保留样卷右上角的 hover 删除“×”。
- 点击后展示二次确认弹窗，明确说明会同时删除该样卷的全部页面。
- 点击“确认删除”立即删除样卷并关闭弹窗。
- 点击“取消”、遮罩空白处或按 Escape 关闭弹窗，不修改数据。
- 点击弹窗内部其他区域不触发取消。

当前故障的根因是遮罩层和取消操作共用 `data-action`。确认按钮位于遮罩内部，事件通过 `closest()` 查找取消动作时先匹配祖先遮罩并提前返回，导致确认分支永远无法执行。修复时按明确的按钮动作优先分发事件，并只在 `event.target` 为遮罩本身时执行遮罩取消。

### 单张纸

- 待确认编辑页保留页面卡片右上角的 hover 删除“×”。
- 点击后立即删除该页，不展示二次确认弹窗。
- 删除后在底部状态区域展示“已删除……第 N 页”的轻提示。

### 共同规则

- 删除后立即刷新样卷数量、页数和页面顺序。
- 删除继续复用 `removeSampleGroup` 和 `removeSamplePage` 纯函数。
- 若目标已不存在，操作不改变数据。
- 允许产生空样卷或清空全部样卷；最终确认仍由现有非空校验阻止创建无有效页面的任务。
- 已确认历史采集任务保持只读，不渲染删除入口。

## 批改题目初始状态

- 作业和考试批改页中的所有题目首次进入均为“待确认”。
- 页面默认选中第一道待确认题，而不是固定题号或预置完成题。
- 老师确认当前题后，将该题改为“已完成”，并自动定位下一道待确认题。
- 点击“确认全部题目批改/赋分”后，所有题目改为“已完成”。
- 全部题目完成时，继续沿用现有逻辑将作业列表对应任务状态回写为“已确认”。

## 逐题进度持久化

使用独立的本地状态保存逐题确认进度：

```text
fxGradingProgress = {
  version: 1,
  tasks: {
    [taskId]: {
      completedQuestionIds: [1, 2, 3],
      updatedAt: 0
    }
  }
}
```

- 状态按 `taskId` 隔离，不同作业或考试互不影响。
- 每次确认单题或确认全部后立即写入。
- 刷新批改页时读取当前任务的已确认题目 ID，恢复对应题目的“已完成”状态。
- 恢复后自动选中第一道仍为“待确认”的题目；若全部完成，则选中第一题并展示全部确认完成态。
- 没有 `taskId` 的内置演示入口使用稳定的回退任务键，保证刷新行为一致。
- 无效或过期的题目 ID 被忽略；本地状态解析失败时回退为全部待确认，不阻塞页面。

## 验收标准

1. 整个样卷删除仍需二次确认，“确认删除”可正常执行。
2. 取消、遮罩空白处和 Escape 可关闭样卷删除弹窗，弹窗内部点击不会误取消。
3. 单页删除不弹窗，点击后立即生效并显示提示。
4. 已确认只读页不显示样卷或单页删除入口。
5. 所有批改题目首次进入均显示“待确认”，默认定位第一道待确认题。
6. 单题确认后自动定位下一道待确认题。
7. 刷新后保留已确认题目状态，并继续定位第一道待确认题。
8. 全部题目确认后，作业列表对应任务状态为“已确认”。
9. 现有拖拽、添加样卷、任务确认、考试赋分和历史只读流程继续通过回归测试。
