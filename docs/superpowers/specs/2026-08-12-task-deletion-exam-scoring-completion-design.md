# 样卷删除、考试赋分与完成状态回写设计

## 目标

在现有采集确认、任务列表和按题批改流程上补齐两类能力：

1. 待确认采集任务中的整个样卷和单个样卷页均可删除，示例页内容逐页不同。
2. 采集生成的考试使用赋分交互；全部题目确认后，任务列表状态回写为“已确认”。

已有约束保持不变：历史采集任务确认后只能查看，不能再编辑或删除样卷及页面；作业列表不提供删除操作，系统不会自动删除原有任务。

## 作业列表

作业列表仅支持进入批改，不展示 hover 删除“×”或删除确认弹窗。若浏览器中残留旧版本的任务删除状态，加载列表时清除该状态，保证内置任务重新展示。

## 样卷与页面删除

删除能力只出现在待确认编辑页。已确认历史任务的查看模式继续保持只读，不出现删除入口。

样卷删除按钮位于样卷容器右上角。样卷页删除按钮位于页面卡片右上角；hover 或键盘聚焦对应对象时显示“×”。点击后均打开二次确认弹窗：

- 删除样卷：弹窗明确提示将同时删除该样卷中的全部页面。
- 删除页面：弹窗展示样卷名称和页码，仅删除目标页面。

确认删除后更新当前内存中的 `groups` 并重新渲染。允许删除到没有样卷或没有有效页面；此时沿用已有确认校验，阻止创建空任务并提示老师先保留有效样卷页面。

## 考试赋分路由

采集生成任务进入批改页时携带稳定的 `taskId`、任务名称、类型、班级、人数和页数。

- `task.kind === "考试"` 时使用 `mode=exam`，复用现有考试赋分交互。
- 其他任务使用 `mode=homework`，复用现有作业批改交互。

不新增第二套批改页面，避免作业与考试的题目确认逻辑分叉。考试模式继续展示平均分、题目得分以及“确认本题赋分”等现有文案。

## 全部题目确认与状态回写

批改页通过 URL 中的 `taskId` 识别当前任务。每次确认单题以及点击“确认全部题目”后，都检查当前任务是否所有题目均为 `completed`。

当全部题目完成时：

- 将该 `taskId` 写入本地任务完成状态，值为“已确认”。
- “确认全部”按钮切换为完成态并禁用。
- 返回或刷新作业列表后，对应任务的 `status` 和 `listTag` 均显示“已确认”。
- 状态按任务 ID 隔离，不影响其他作业或考试。

采集生成任务的完成状态同时合并回 `fxGeneratedCollectionTasks`，从而保留其名称、类型和其他元数据。内置演示任务通过同一份任务完成状态覆盖默认列表状态。

## 弹窗与可访问性

样卷和样卷页删除复用统一的确认弹窗视觉与交互模式：

- 使用 `role="dialog"`、`aria-modal="true"` 和明确标题。
- “取消”为默认安全操作，“确认删除”为危险操作样式。
- 点击遮罩或按 Escape 等同取消，不执行删除。
- 删除按钮具有包含对象名称的 `aria-label`，并可通过键盘聚焦显示。

## 测试

新增回归测试覆盖：

- 作业列表不渲染删除入口或删除确认逻辑。
- 待确认页可删除整个样卷和单页，查看模式不显示删除入口。
- 同一样卷中的每一页使用不同示例题目内容。
- 删除操作必须经过二次确认，取消不改变数据。
- 采集生成考试使用 `mode=exam`，作业使用 `mode=homework`。
- 单题逐一确认至全部完成、以及直接确认全部，两条路径都会回写“已确认”。
- 列表只更新对应任务的状态，其他任务不受影响。

原有采集确认、五秒识别进度、历史任务只读、样卷换行和列表原始任务保留测试继续全部通过。
