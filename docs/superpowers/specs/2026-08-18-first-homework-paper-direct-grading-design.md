# 第一份作业纸面直接批改设计

## 目标

在第一份作业 `cluster-homework` 的“按学生批改”视图中，把学生作业本身改为批改入口。教师悬停题目时看到明确的选中反馈，点击题目即可在“对、错、半对”之间切换；右侧结构化批改工具不再展示。

## 范围

- 仅作用于 `taskId=cluster-homework` 的按学生批改视图。
- 按题批改视图、其他作业和考试继续使用现有交互。
- 保留左侧学生列表、学生切换、作业分页、底部“确认批改”和“一键确认批改”。
- 纸面点击与按题批改共用 `question.students[].result`，切换视图后结果即时同步。

## 方案比较

### 方案 A：按任务开启纸面直批（采用）

通过 `usesPaperDirectGrading` 判断第一份作业。在该任务中隐藏每页右侧工具栏，为题目增加可点击语义和悬停态，并复用 `updateStudentResult` 写回状态。

优点：满足“第一份作业”的明确范围，不影响其他任务；数据同步路径最短；可继续复用现有确认逻辑。

### 方案 B：所有作业统一移除右侧工具

实现更少，但会改变其他作业和考试，超出本次范围。

### 方案 C：在作业题目上叠加浮动批改控件

能展示三个显式按钮，但仍属于额外工具，违背“结构化的批改工具不需要了”，也会遮挡作业内容。

## 交互设计

- 默认：题目保持作业纸排版和当前批改标记。
- Hover / 键盘聚焦：整题出现浅蓝底、品牌色描边和左侧强调线，表示当前点击目标。
- 点击：
  - 未批改 → 对
  - 对 → 错
  - 错 → 半对
  - 半对 → 对
- 键盘：聚焦题目后按 Enter 或 Space，执行同一循环。
- 更新后：纸面标记、学生正确率、确认状态和按题批改分组同步刷新。

## 页面结构

- 直批任务的 `.student-page-row` 改为单列，只保留居中的 `.student-paper-stage`。
- 非直批任务仍渲染 `.student-tool-panel`，保持现有结构化批改能力。
- 多页作业继续由同一个 `.student-page-stack` 承载，每页题目均可直接操作。

## 可访问性

- 可批改题目使用 `role="button"`、`tabindex="0"`。
- `aria-label` 包含题号、当前结果和点击提示。
- `:focus-visible` 与 hover 使用一致的选中反馈。

## 验收标准

1. 第一份作业切到按学生批改后，不显示右侧结构化批改工具。
2. 每一页的每一道题 hover 时整题高亮。
3. 点击题目按“对 → 错 → 半对 → 对”循环；未批改首次点击为“对”。
4. 纸面标记立即更新，切回按题批改后结果一致。
5. Enter / Space 可以触发同一切换。
6. 其他作业、考试的结构化批改工具不受影响。
7. 底部单学生确认按钮及左侧一键确认按钮保持原位置与功能。
